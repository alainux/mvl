A framework for small, functional languages

Meaning is the interface.
Language is the implementation.

Minimum Viable Language is a specification for building deliberately small, compositional subsets of natural languages. Define the communicative meaning once. Apply typed operations. Realize the result through a language-specific grammar.

01 / The design

One abstract system.
Many concrete grammars.

MVL does not define another pidgin or a global grammar. It defines a shared meaning model and a contract that natural-language adapters must implement.

I · SEMANTICS
Typed primitives

Person, Thing, Place, Event. Values have meaning, not grammatical gender or word order.

EVENT(help, addressee, speaker)
→
II · COMPOSITION
Pure operators

CAN, NOT, WHEN, ASK and PLEASE transform a meaning tree with type constraints.

ASK(CAN(event))
→
III · REALIZATION
Language adapters

Each adapter handles agreement, inflection, case, word order and surface conventions.

linearize(tree, lang)
Design invariant

The same well-typed meaning tree must be accepted by every conforming language adapter—or the adapter must explicitly report an unsupported capability. No silent word-for-word substitution.

02 / Capability profiles

Define viability. Derive the subset.

A minimum viable language begins with a target set of communicative capabilities. The specification computes the smallest operator dependency closure that supports those capabilities. Grammar coverage is then implemented and tested independently by each language adapter.

04 / Rules of composition

Operators are the grammar
of meaning.

Operators form a typed expression tree. A modal cannot be applied to an arbitrary object; PLEASE cannot decorate a declaration; some predicate–modal combinations are excluded from this starter profile.

example.mvl
const e = EVENT(help, addressee, speaker);
const p = CAN(e);
const q = ASK(p);
const polite = PLEASE(q);

linearize(polite, 'de');
linearize(polite, 'fr');
linearize(polite, 'es');
05 / Concrete syntax

Three independent adapters.

The adapters implement the same semantic contract; they do not share a universal surface word order. They decide how each concept is expressed in ordinary German, French, and Spanish.

This is a bounded experimental grammar, not comprehensive coverage or a standardized language proficiency level. Unsupported forms are rejected by the type system rather than guessed.

07 / Implementer contract
How to add a language.
A new implementation is a realizer with a bounded feature profile and regression tests—not a translated dictionary of outputs.
01
Implement the interface
Expose profile and realize(tree); consume the shared AST without mutating it.
02
Declare the boundary
Specify register, regional variety, supported predicates, morphosyntactic features, and missing coverage.
03
Make grammar explicit
Implement case, agreement, conjugation, constituent ordering, negation, and question realization using reusable rules.
04
Prove the contract
Test the same tree corpus for every language. Check grammatical examples manually; automation alone cannot guarantee naturalness.
